## Frozen contracts

Both consumer repos are implemented **in parallel against these exact signatures**. They are
authored once in Wave 1 and must not be renegotiated by a Wave 2 agent. If an agent believes
a contract is wrong, it must stop and report rather than change it — a unilateral change
silently breaks the other track.

### `scoring.ts` (final, complete file — shared repo)

```ts
import type { PlayerEntry, PlayerIndex, Round } from "./types";

export const SCORE_TABLE: Record<number, number> = {
  1: 1,  2: 2,  3: 3,  4: 4,
  5: 10, 6: 12, 7: 14, 8: 16,
  9: 27, 10: 40, 11: 44, 12: 48, 13: 52,
};

/**
 * harshDoubles: when true, a missed bid costs the SCORE_TABLE value rather than
 * the raw bid (call 5, miss → -10 instead of -5). Bids 2-4 are identical either way.
 */
export function playerScore(called: number, obtained: number, harshDoubles: boolean): number {
  const value = SCORE_TABLE[called] ?? called;
  return obtained >= called ? value : -(harshDoubles ? value : called);
}

export function calcRound(
  entries: [PlayerEntry, PlayerEntry, PlayerEntry, PlayerEntry],
  harshDoubles: boolean,
): { teamAScore: number; teamBScore: number } {
  const teamAScore =
    playerScore(entries[0].called, entries[0].obtained, harshDoubles) +
    playerScore(entries[1].called, entries[1].obtained, harshDoubles);
  const teamBScore =
    playerScore(entries[2].called, entries[2].obtained, harshDoubles) +
    playerScore(entries[3].called, entries[3].obtained, harshDoubles);
  return { teamAScore, teamBScore };
}

export function runningTotals(rounds: Round[]): { a: number; b: number } {
  let a = 0;
  let b = 0;
  for (const round of rounds) {
    a += round.teamAScore;
    b += round.teamBScore;
  }
  return { a, b };
}

export function playerCumulativeScore(
  rounds: Round[],
  playerIndex: PlayerIndex,
  harshDoubles: boolean,
): number {
  return rounds.reduce((sum, r) => {
    const e = r.entries[playerIndex];
    return sum + playerScore(e.called, e.obtained, harshDoubles);
  }, 0);
}

export function playerStats(
  rounds: Round[],
  playerIndex: PlayerIndex,
): { makeRate: number; avgCalled: number; avgObtained: number } {
  if (rounds.length === 0) {
    return { makeRate: 0, avgCalled: 0, avgObtained: 0 };
  }

  let made = 0;
  let totalCalled = 0;
  let totalObtained = 0;

  for (const round of rounds) {
    const entry = round.entries[playerIndex];
    totalCalled += entry.called;
    totalObtained += entry.obtained;
    if (entry.obtained >= entry.called) {
      made += 1;
    }
  }

  return {
    makeRate: made / rounds.length,
    avgCalled: totalCalled / rounds.length,
    avgObtained: totalObtained / rounds.length,
  };
}
```

`runningTotals` and `playerStats` deliberately keep their signatures — they read stored
round snapshots and raw entries, never the rule.

**The parameter is required, not defaulted, on purpose.** `tsc --noEmit` then enumerates
every call site, which *is* each track's checklist. An agent that "fixes" a type error by
adding `= false` to the signature has defeated the mechanism — do not do this.

### T-A — Android keyboard & scroll (mobile, independent of everything else)

**Root cause (established, do not re-investigate):** `app.json:25` sets
`"edgeToEdgeEnabled": true`. Under Expo SDK 54 edge-to-edge the window no longer resizes for
the IME the way plain `adjustResize` did, so any screen without an explicit
`KeyboardAvoidingView` loses the area under the keyboard — content below becomes unreachable
*and* the ScrollView gains no scroll height, which users report as "not scrollable". Both
Discord reports came from the same device minutes apart and were typed into the feedback form
on the Settings screen — the screen that breaks.

Expo's SDK 54 keyboard guide prescribes `behavior={Platform.OS === 'ios' ? 'padding' : undefined}`.
On Android, merely having the KAV mounted is the fix; **`behavior="height"` is the broken
combination.** Use exactly this expression in all three places.

**A1 — `src/screens/settings/SettingsScreen.tsx` (the reported screen)**
- Line 2: add `KeyboardAvoidingView` to the `react-native` import. `Platform` is already imported.
- Wrap the `ScrollView` at line 65 in
  `<KeyboardAvoidingView style={{ flex: 1 }} behavior={Platform.OS === 'ios' ? 'padding' : undefined}>`.
- Add `paddingBottom: 48` to `contentContainerStyle` so the Send button clears the IME.
- Add `keyboardDismissMode="on-drag"`.
- `keyboardShouldPersistTaps="handled"` is already present — keep it.

**A2 — `src/screens/game/SetupScreen.tsx:58-61`**
Same bug class, currently latent. It has a KAV but uses the broken `behavior="height"` on
Android. Change to `undefined`. Affects the Score Limit input and the Start button.

**A3 — `src/components/EditRoundModal.tsx:63-77`** — genuinely non-scrollable, independent
of the keyboard. An absolutely-positioned sheet at `bottom: 0` holding 8 `NumberStepper`s, a
multiline comment `TextInput` and Save, with no ScrollView. On a short screen the title/Cancel
row overflows off the top with no way to reach it.
- Remove `position: 'absolute'` / `bottom` / `left` / `right` — the parent already does
  `justifyContent: 'flex-end'`, and the absolute positioning is what defeats it.
- Add `maxHeight: '90%'` to the sheet.
- Move the body (lines 85-148) into a `ScrollView` with `keyboardShouldPersistTaps="handled"`.
  Keep the title/Cancel row pinned outside it.
- Wrap in a `KeyboardAvoidingView` **inside** the `Modal` — RN `Modal` is its own window and
  does not inherit the host window's soft-input handling.
- Add `statusBarTranslucent` and `navigationBarTranslucent` to the `Modal` for edge-to-edge.

**Explicitly do not:**
- Add `react-native-keyboard-controller` or any keyboard library. Core `KeyboardAvoidingView`
  covers all three cases. If manual testing later shows the multiline inputs still misbehave,
  that is a follow-up decision, not this track's call.
- Set `android.softwareKeyboardLayoutMode: "pan"`. That is the fix for tab bars being pushed
  up, and `RootTabs.tsx:25` already sets `tabBarHideOnKeyboard: true`. Switching to `pan`
  would remove the window resize that A1 and A2 depend on.

**Done when:** `npx tsc --noEmit` clean, and a written self-review confirming the three edits
against the descriptions above. Runtime verification is Wave 3 (needs a device).

## Repeatability (the "can be updated from" requirement)

After this release the update path for any future change is:
1. Scoring rule change → edit `src/shared/scoring.ts` in either repo → `pnpm scoring:push`,
   then `pnpm scoring:pull` in the other. Write it once.
2. UI change → normal per-repo work.
3. Ship → push web `main` (auto-deploys); `fastlane ios release`; `fastlane android release`.

**Known ceiling:** `git subtree pull` is manual, so the two mounts can sit at different
commits. Acceptable for one developer across two repos. If it ever bites, the upgrade path
is a CI check that fails when `src/shared` doesn't match the shared repo's `main` — not worth
building today.

**Deferred, tracked:** the `GOOGLE_PLAY_JSON_KEY_PATH` / `SUPPLY_JSON_KEY` mismatch in
`fastlane/Fastfile` (see Wave 0). Works via env fallback; clean up in a quiet moment, not
during a release.
